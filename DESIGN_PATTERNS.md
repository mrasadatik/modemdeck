# Design Patterns

| Pattern                  | Where it lives                                                                                                               | Why                                                                                                                         |
| ------------------------ | ---------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------- |
| **Factory / Strategy**   | `src/infrastructure/platform/registry.ts` — `createDefaultProvider` picks the concrete `PlatformProvider` for the current OS | New platforms plug in by adding a provider, not by patching call sites                                                      |
| **Adapter**              | `src/interfaces/http/http-server-adapter.ts`, `SerialTransportPort`, `Repository`, `SenderAdapter` over Windows provider     | Concrete side-effects are behind ports; the domain/application layers are unaffected by HTTP, serial or persistence details |
| **Repository**           | `src/infrastructure/persistence/sqlite-repository.ts` via `Repository<ModemDatabase>`                                        | Single access point for all persistence; also the seam for encryption and state-wiping                                      |
| **Observer / EventBus**  | `src/infrastructure/events/event-bus.ts`, `src/interfaces/http/sse-hub.ts`                                                   | Decouples modem/runtime events from UI updates                                                                              |
| **Command / Queue**      | `src/infrastructure/at/at-engine.ts` — serialized pending commands                                                           | Prevents AT command overlap on a single serial port                                                                         |
| **Strategy**             | `src/domain/services/sms-codec.ts` (`SmsEncodingStrategy`), `DataTransportSelector`                                          | GSM-7/UCS2 encoding, PDU encoding and transport scoring are swappable algorithms                                            |
| **State**                | `src/bootstrap/session.ts`, `ModemLifecycle` status                                                                          | Explicit connection/lock lifecycle; SIM swap, auto-lock and manual lock all funnel through clear states                     |
| **Facade**               | `src/application/modem-services.ts` — `SmsIngestionService`, `UssdSessionManager`, `NetworkService`                          | Complex modem command sequences are hidden behind one use-case object                                                       |
| **Decorator / Pipeline** | `ModemLifecycle` retry timers, `SmsIngestionService.ingest → publish → purge`                                                | Cross-cutting behaviors are chained around the core use-case                                                                |
| **Builder-ish**          | `createApp` composition root in `src/bootstrap/app.ts`                                                                       | All dependencies are assembled at runtime from one place                                                                    |
| **Template Method**      | `tsconfig`+vite → compiled server, Svelte build is a fixed pipeline                                                          | Build and test pipelines are predictable                                                                                    |

Anything read from `src/` should stay against these seams — concrete platforms or encryption schemes are details, not architecture.
